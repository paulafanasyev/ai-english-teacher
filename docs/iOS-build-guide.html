Требования

Собрать iOS-приложение можно только на Mac — это требование Apple, обойти его нельзя (в отличие от Android, который собирается на любой ОС). Понадобится:

  • macOS — актуальная версия (Ventura 13+ или новее, под требования Xcode 15).
  • Xcode 15+ — из Mac App Store. Это требование Capacitor 6. Запустите его один раз, чтобы догрузились компоненты.
  • Node.js 18+ — nodejs.org. Проверка: node -v
  • CocoaPods — менеджер нативных зависимостей iOS (ставим в шаге 2).
  • Apple Developer Program — $99/год. Нужен для запуска на реальном iPhone, TestFlight и публикации. Для теста в симуляторе аккаунт не обязателен.
🍏

Нет Mac? iOS-сборку нельзя выполнить на Windows/Linux. Варианты: облачный Mac (MacStadium, Scaleport), CI (Xcode Cloud, Codemagic, GitHub Actions с macOS-раннером) или Mac у коллеги. Для быстрой установки на iPhone без App Store подойдёт PWA («Поделиться → На экран „Домой“»).

2

CocoaPods и Command Line Tools

Установите инструменты командной строки Xcode и CocoaPods.

терминал
# инструменты командной строки Xcode
xcode-select --install

# принять лицензию Xcode (один раз)
sudo xcodebuild -license accept

# CocoaPods (через встроенный Ruby)
sudo gem install cocoapods

# проверка версий
xcodebuild -version      # Xcode 15.x
pod --version            # 1.11+
💡

На Apple Silicon (M1/M2/M3), если pod install капризничает, поставьте CocoaPods через Homebrew: brew install cocoapods. Это часто стабильнее системного Ruby.

3

Инициализация проекта

Capacitor уже в зависимостях (@capacitor/ios v6.1), конфиг apps/web/capacitor.config.json заполнен (appId com.aiteacher.app, webDir dist, contentInset: "always"). Установите зависимости, соберите веб-билд и создайте нативный iOS-проект.

из корня репозитория
cd apps/web

npm install                 # зависимости, включая Capacitor 6
npm run build               # Vite собирает веб-приложение в apps/web/dist

npx cap add ios             # создаёт папку ios/ и запускает pod install (один раз)
npx cap sync ios            # копирует dist/ в нативный проект + pod install
npx cap open ios            # открывает проект в Xcode

Что происходит:

  • npx cap add ios — разворачивает Xcode-проект в папке ios/ с вашим appId и ставит нативные зависимости через CocoaPods.
  • npx cap sync ios — переносит свежий dist/ внутрь iOS-проекта и обновляет поды. Запускайте после каждого npm run build (или ярлык npm run cap:sync).
  • npx cap open ios — открывает ios/App/App.xcworkspace в Xcode.
⚠️

Всегда открывайте App.xcworkspace (это делает cap open), а не App.xcodeproj — иначе Xcode не увидит зависимости CocoaPods и сборка упадёт.

4

Запуск в симуляторе и на iPhone

Симулятор (без аккаунта разработчика)

  1. В Xcode вверху выберите схему App и любой симулятор (напр. iPhone 15).
  2. Нажмите ▶ Run (или Cmd+R). Приложение соберётся и откроется в симуляторе.

Реальный iPhone

  1. Подключите iPhone кабелем, разблокируйте, нажмите «Доверять этому компьютеру».
  2. Настройте подпись (шаг 6), выберите устройство в списке и нажмите ▶ Run.
  3. Первый запуск: на iPhone откройте Настройки → Основные → VPN и управление устройством → доверьте профилю разработчика.
🖥️

Открыть проект из терминала в любой момент: npx cap open ios или ярлык npm run cap:ios.

Иконки и сплэш-экран

Официальный инструмент @capacitor/assets сгенерирует иконку приложения и заставку из одной картинки.

генерация ассетов для iOS
# положите исходники в apps/web/resources/
#   icon.png    — 1024×1024 (иконка App Store)
#   splash.png  — 2732×2732 (заставка)

npm i -D @capacitor/assets

npx capacitor-assets generate --ios \
  --splashBackgroundColor '#7c3aed' \
  --splashBackgroundColorDark '#4c1d95'

После генерации: npm run build → npx cap sync ios. Цвета совпадают с фирменным фиолетовым приложения (#7c3aed).

6

Подпись: Apple Developer

Apple требует подписывать любое приложение для устройства/публикации. Проще всего — автоматическая подпись в Xcode.

  1. Добавьте свой Apple ID в Xcode: Xcode → Settings → Accounts → «+» → Apple ID. Войдите под аккаунтом Apple Developer Program.
  2. В навигаторе выберите проект App → таргет App → вкладка Signing & Capabilities.
  3. Включите «Automatically manage signing».
  4. В поле Team выберите вашу команду разработчика.
  5. В Bundle Identifier укажите com.aiteacher.app (должен совпадать с appId и быть уникальным в App Store — при конфликте добавьте суффикс, напр. com.вашакомпания.aiteacher).
🔐

При автоматической подписи Xcode сам создаёт и обновляет сертификаты (Development / Distribution) и provisioning-профили. Ручной режим (Manual signing) нужен только для сложных CI-сценариев.

🔒

Сохраните доступ к аккаунту Apple Developer. При включённом App Store Connect-хранении ключей потеря доступа к аккаунту = невозможность выпускать обновления. Держите под рукой Team ID и данные для входа.

7

Archive → TestFlight → App Store

7.1  Версия и номер сборки

Во вкладке таргета General задайте Version (напр. 1.0.0, видна пользователям) и Build (напр. 1, увеличивайте на +1 при каждой загрузке в App Store Connect).

7.2  Создать архив

  1. Вверху Xcode выберите цель «Any iOS Device (arm64)» — не симулятор (иначе пункт Archive будет неактивен).
  2. Меню Product → Archive. Xcode соберёт релизную сборку и откроет окно Organizer.

7.3  Загрузить в App Store Connect

  1. Заранее создайте запись приложения в App Store Connect → My Apps → «+» → New App с тем же Bundle ID com.aiteacher.app.
  2. В Organizer выберите архив → Distribute App → App Store Connect → Upload. Xcode проверит и зальёт сборку.
  3. Сборка обрабатывается ~5–30 мин, затем появляется во вкладке TestFlight.

7.4  TestFlight (бета-тест)

  • Internal Testing — до 100 членов команды, доступ почти сразу.
  • External Testing — до 10 000 тестеров по ссылке/почте; требуется краткая проверка Apple (Beta App Review).

7.5  Публикация в App Store

  1. В App Store Connect заполните карточку: название, описание, ключевые слова, скриншоты для нужных размеров экрана, значок 1024×1024.
  2. Заполните App Privacy (какие данные собираются), возрастной рейтинг, категорию и цену (Free).
  3. Выберите загруженную сборку → Add for Review → Submit for Review.
📦Проект для сборки:  ios/App/App.xcworkspace · схема App

Онлайн-режим с вашим сервером (опционально)

По умолчанию приложение упаковывает офлайн-демо (данные на устройстве). Чтобы работать с вашим backend (Node + PostgreSQL: логин по JWT, кабинеты, дневник онлайн) — соберите веб-часть с адресом API и пересинхронизируйте.

сборка в серверном режиме
cd apps/web

VITE_API_URL=https://api.вашдомен.com npm run build
npx cap sync ios

# дальше — обычный Run или Archive из Xcode
⚠️

iOS по умолчанию (App Transport Security) требует HTTPS с валидным сертификатом. Обычный TLS-домен работает без правок; для самоподписанных сертификатов пришлось бы менять Info.plist (не рекомендуется для релиза). Настройка сервера — в DEPLOY.md.

Частые ошибки и решения

ОшибкаПричина и решение
Signing for "App" requires a development teamНе выбрана команда. Вкладка Signing & Capabilities → включить Automatically manage signing → выбрать Team (шаг 6).
No account for team ... / Failed to register bundle identifierApple ID не добавлен или Bundle ID занят. Добавьте аккаунт в Xcode → Settings → Accounts; при конфликте смените Bundle ID на уникальный.
Command PhaseScriptExecution failed (node not found)Xcode не находит Node. Создайте ios/App/.xcode.env со строкой export NODE_BINARY=$(command -v node).
pod install падает / Unable to find a specificationОбновите репозиторий подов: cd ios/App && pod repo update && pod install. На M-чипах помогает brew install cocoapods.
Пункт Archive неактивен (серый)Выбран симулятор. Смените цель на «Any iOS Device (arm64)» (шаг 7.2).
Белый экран после запускаНе синхронизирован свежий билд. Выполните npm run build && npx cap sync ios.
«Untrusted Developer» на iPhoneНастройки → Основные → VPN и управление устройством → доверьте профилю (шаг 4).
Открыли .xcodeproj — нет зависимостейНужно открывать App.xcworkspace. Запустите npx cap open ios.

Шпаргалка команд

Полный цикл от нуля до загрузки в App Store Connect:

всё вместе
# --- разовая настройка ---
xcode-select --install
sudo gem install cocoapods

cd apps/web
npm install
npm run build
npx cap add ios

# --- каждая новая сборка ---
cd apps/web
npm run build && npx cap sync ios
npx cap open ios              # → в Xcode: подпись, Run или Archive

# в Xcode:
#   Run (Cmd+R)                — симулятор / устройство
#   Product → Archive          — релизная сборка (цель = Any iOS Device)
#   Organizer → Distribute App — загрузка в App Store Connect / TestFlight
ОбъектПуть / место
Xcode-проектios/App/App.xcworkspace
Podfile (нативные зависимости)ios/App/Podfile
Архив (.xcarchive)Xcode → Window → Organizer
Бета и релизappstoreconnect.apple.com → TestFlight / App Store
📱

Быстрый путь на iPhone без App Store — PWA: приложение уже содержит manifest + service worker, ставится через Safari «Поделиться → На экран „Домой“» и работает офлайн. Capacitor нужен именно для TestFlight и App Store. Android-версия — в отдельной инструкции по сборке APK.
